# 完整日历行程规划器设计

## 1. 目标

把当前自动生成、只读的每日行程升级为可编辑的完整日历规划器。用户应能从地图路线开始，得到按日期组织的行程，继续调整城市停留天数、跨城交通、景点活动和住宿信息，并将同一份计划用于地图展示、本机保存、分享和旅游指南导出。

第一版定位为本地规划工具，不接入实时车次、酒店价格、余票或景点开放时间接口。用户手动填写交通和住宿信息，景点优先从项目现有数据中选择，也允许添加自定义活动。

## 2. 已确认的产品决策

- 采用完整日历规划器，而不是在现有只读日程上叠加临时覆盖。
- 桌面端支持拖拽，手机端支持移动菜单；移动菜单同时作为键盘和无拖拽环境的通用兜底。
- 同一城市可连续停留 `1-7` 天。
- 用户手动编辑后，路线变化采用增量合并，不重新打乱已有日期。
- 出发日期可选。设置后显示日期和星期，未设置时只显示“第 N 天”。
- 车次和酒店由用户填写，景点从现有数据选择或自定义，不依赖第三方实时接口。
- 导出提供 Markdown 和可打印 HTML 两种旅游指南格式。

## 3. 范围

### 3.1 本次包含

- 行程名称、可选出发日期、节奏和总天数。
- 路线首次自动排期以及后续增量合并。
- 每日城市、过夜城市和城市停留天数编辑。
- 交通、景点/活动、自由活动和住宿编辑。
- 城市与活动的跨日移动、日内排序和一次撤销。
- 时间冲突、交通衔接、游玩时间和住宿城市校验。
- `TripPlan v1` 到 `TripPlan v2` 的本地存档及分享数据迁移。
- 本机自动保存、分享链接、行程文件导入导出。
- Markdown 旅游指南和可打印 HTML 旅游指南。
- 桌面与移动端完整操作路径。

### 3.2 本次不包含

- 实时余票、车次、房价、库存和门票查询。
- 订单、支付、账号、云同步和多人协作。
- 根据营业时间或实时路况进行全自动最优解计算。
- 城市内逐段公共交通导航。
- 依赖在线地图瓦片的导出地图截图。

这些能力可以在稳定的 `TripPlan v2` 模型上继续扩展，但不进入本次验收范围。

## 4. 核心用户流程

1. 用户在地图上依次选择城市或区县，系统按照路线、估算交通时长和当前节奏首次生成日历。
2. 用户可填写行程名称和出发日期，并通过拖拽或移动菜单调整城市所属日期。
3. 用户为城市设置 `1-7` 天停留时间。系统新增或移除连续日期，并保留仍然有效的手动活动。
4. 用户在每日时间轴中添加交通、景点/活动和自由活动，并填写当天住宿。
5. 系统即时给出冲突和可行性提醒，但除格式错误外不阻止保存。
6. 每次有效编辑后自动保存。刷新页面、分享链接恢复或导入行程文件时，恢复同一份计划。
7. 用户导出 Markdown 或可打印 HTML 旅游指南；导出内容与页面当前日历一致。

## 5. 数据模型

日历是行程的唯一业务数据源。地图路线、汇总信息、每日提醒和导出文本都是从日历推导的结果，避免路线状态与日历状态互相覆盖。

```js
{
  version: 2,
  id: "trip-<stable-id>",
  name: "华中五日行",
  startDate: "2026-10-01", // 可为 null
  pace: "standard",
  days: [
    {
      id: "day-<stable-id>",
      cityEntries: [
        {
          id: "city-entry-<stable-id>",
          visitId: "visit-<stable-id>",
          placeId: "henan-zhengzhou-0",
          manuallyPlaced: true
        }
      ],
      overnightPlaceId: "henan-zhengzhou-0",
      items: [],
      lodging: null,
      manuallyEdited: true
    }
  ],
  savedAt: "2026-07-13T12:00:00.000Z"
}
```

### 5.1 日期

- `days` 数组顺序是日期顺序，`dayNumber` 不持久化，由数组下标加一得到。
- 设置 `startDate` 时，具体日期由开始日期和数组下标推导；未设置时日期为 `null`。
- 移动或插入日期时不重建已有 `day.id`，以保护表单焦点、拖拽状态和关联内容。

### 5.2 城市停留

- 同一次连续停留使用相同 `visitId`，每天各有一个独立 `cityEntry`。
- 停留天数由具有相同 `visitId` 的连续日期数量推导。
- 增加停留天数时，在该次访问的末尾插入日期；减少时从末尾开始删除空白日期。
- 被删除日期含有手动交通、活动或住宿时，必须先让用户选择移动内容或确认删除。
- 一天可以包含多个城市，`cityEntries` 顺序表示当天实际移动顺序。

### 5.3 时间轴项目

交通项目：

```js
{
  id: "item-<stable-id>",
  type: "transport",
  fromPlaceId: "...",
  toPlaceId: "...",
  serviceNo: "G123",
  startTime: "09:15",
  endTime: "11:42",
  endDayOffset: 0, // 夜间交通为 1
  note: "从东广场进站",
  manuallyEdited: true
}
```

活动项目：

```js
{
  id: "item-<stable-id>",
  type: "activity",
  sourceType: "landmark", // landmark、food、custom、free
  sourceId: "...",        // 自定义项目可为 null
  placeId: "...",
  title: "河南博物院",
  startTime: "14:00",
  endTime: "16:30",
  note: "提前预约",
  manuallyEdited: true
}
```

住宿信息：

```js
{
  placeId: "...",
  name: "二七广场附近酒店",
  address: "...",
  checkInTime: "18:00",
  checkOutTime: "09:00",
  note: "可寄存行李"
}
```

校验结果、交通估算、景点推荐文案和日期显示文本均为派生数据，不写入持久化模型。

## 6. 自动排期与增量合并

### 6.1 首次排期

- 从现有路线段提取有序地点序列。
- 根据当前节奏的每日跨城上限、最大城市数和估算交通时长拆分日期。
- 每天最后抵达地点默认成为过夜城市。
- 初始交通项目可使用现有路线估算生成，但标记为估算值；用户填写后转为手动值。

### 6.2 路线变化

- 使用地点 ID 序列匹配已有城市访问，保留相同地点的 `visitId`、日期和手动内容。
- 新地点优先插入其路线前驱和后继之间最早可用的日期；没有安全位置时新增一天。
- 删除不含手动内容的地点时直接清理对应城市条目和派生交通。
- 删除含手动活动、交通或住宿的地点时，先展示受影响内容并要求确认。
- 用户在日历中改变城市先后顺序后，地图路线按照各城市首次出现的日期和日内顺序重新计算。
- 手动日期不因节奏切换而自动重排；节奏切换只更新提醒。用户主动点击“重新自动排期”时才覆盖手动日期，并在执行前确认。

## 7. 页面结构与交互

### 7.1 行程设置

现有“时间规划”区域顶部增加：

- 行程名称输入框。
- 可清空的出发日期选择器。
- 总天数显示。
- “自动排期”命令。
- 撤销按钮。

总天数由 `days.length` 决定，不提供与日历脱节的独立数字输入。

### 7.2 每日编辑器

每个日期区块显示：

- 第 N 天、具体日期和星期。
- 当天城市与过夜城市。
- 跨城耗时、已安排时长和剩余可用时间。
- 按时间排序的交通与活动列表。
- 住宿摘要。
- 仅属于本日的校验提醒。

城市行程项提供拖拽手柄、停留天数步进器、移动菜单和删除命令。时间轴项目提供编辑、移动、复制和删除命令。熟悉的图标命令带有 `title` 和可访问名称。

### 7.3 桌面端

- 城市可在日期之间拖拽，也可在同一天内调整顺序。
- 活动可调整日内顺序或拖到其他日期。
- 拖拽目标保持稳定高度，并明确显示插入位置。
- 移动菜单始终可用，作为键盘操作和拖拽失败的兜底。

### 7.4 移动端

- 保留现有“地图 / 行程”双视图。
- 城市和活动通过“前一天、后一天、指定日期”菜单移动。
- 编辑表单使用底部抽屉；关闭前校验当前字段，已提交编辑立即保存。
- 不要求触屏拖拽，避免滚动页面时误操作。

### 7.5 撤销与保存反馈

- 使用命令式更新记录最近 `20` 次日历编辑，页面提供一次一步撤销。
- 撤销历史只保留在当前页面会话，不进入分享数据。
- 每次有效编辑后写入本机存档，并显示短暂的“已保存”状态。
- 存储失败时保留页面内状态，并明确提示用户导出行程文件，避免无声丢失。

## 8. 时间和可行性规则

- 默认可规划时段为 `08:00-22:00`，仅用于计算空闲时间和提醒，不限制用户输入。
- 时间字段使用 `HH:mm`；格式无效时不提交该字段。
- `endTime` 早于 `startTime` 时，交通项目可显式选择“次日到达”，对应 `endDayOffset = 1`。
- 普通活动不允许跨日；需要跨日的内容使用交通项目或拆为两个活动。
- 过夜城市默认是当天最后抵达城市，用户可以从当天到达过的城市中修改。
- 逻辑问题以提醒为主，不阻止保存或导出；格式无效和缺失必要关联 ID 时阻止提交当前编辑。

提醒类型包括：

- 同一日期的时间轴项目重叠。
- 活动开始时间早于抵达该城市的时间。
- 跨城耗时超过当前节奏上限。
- 当日剩余可游玩时间不足两小时。
- 过夜城市不在当天城市列表中。
- 住宿城市与过夜城市不一致。
- 交通缺少时间、活动缺少时长或过夜日缺少住宿。

## 9. 保存、迁移和分享

### 9.1 本机存档

- 新存档键使用 `route-studio-trip-v2`。
- 首次读取时优先恢复 v2；没有 v2 时读取现有 v1 数据并迁移。
- v1 路线通过现有自动排期生成 `days`，保留交通方式、节奏和选中地点。
- 迁移成功后保存 v2，同时保留一份 v1 备份，直到用户完成一次新的有效编辑。
- 无法识别的旧字段不阻断恢复；至少保留可识别路线，并提示用户检查重新生成的日历。

### 9.2 分享链接

- 分享负载只包含用户输入和稳定 ID，不包含校验结果、推荐文本或可重新计算的路线估算。
- 分享数据带有明确版本号，并使用 URL 安全编码放入 hash，服务端不接触行程内容。
- 生成后检查最终 URL 长度。超过 `12000` 个字符时不复制高风险长链接，改为导出 `.trip.json` 行程文件并提示接收者导入。
- 导入文件时校验版本和数据形状；失败时不覆盖当前行程。

## 10. 旅游指南导出

Markdown 与 HTML 使用同一个规范化导出模型，保证两种格式内容一致。导出顺序为：

1. 行程封面：名称、日期范围、总天数、城市顺序和节奏。
2. 路线概览：城市访问顺序、估算距离和跨城时间。
3. 每日计划：日期、城市、交通、按时间排序的活动、住宿和提醒。
4. 行前检查：未填写交通时间、住宿和冲突项目汇总。
5. 数据说明：估算信息不代表实时车次、营业时间或库存。

可打印 HTML 使用内嵌样式生成独立文件，不依赖应用页面 CSS 或在线资源。路线概览使用文字和表格，不嵌入可能因跨域或离线环境失效的地图瓦片。用户可在浏览器中直接打印为 PDF。

## 11. 代码边界

新增三个独立浏览器模块：

- `trip-plan.js`：模型创建、迁移、自动排期、增量合并、命令更新、序列化和校验。该模块不访问 DOM。
- `trip-editor.js`：日历渲染、事件代理、拖拽适配、移动菜单、编辑抽屉和撤销入口。
- `guide-export.js`：规范化导出模型、Markdown 生成和独立 HTML 生成。

现有 `app.js` 负责地图、地点数据、路线估算和三个模块之间的协调，不继续承载日历业务规则。

核心数据流：

```text
地图选点或路线变化
  -> trip-plan 增量合并
  -> trip-editor 呈现和编辑
  -> trip-plan 校验并自动保存
  -> 地图、汇总、分享和 guide-export 读取同一个 TripPlan
```

发布版以 `public/static-site/` 为运行入口。根目录静态文件在本次实现中保持同步，避免 README 所述本地预览与线上版本行为不同。

## 12. 测试策略

使用 Node 内置测试运行器测试纯业务模块，至少覆盖：

- v1 存档迁移为 v2。
- 无出发日期和有出发日期时的日期推导。
- 首次自动排期。
- 城市连续停留 `1-7` 天。
- 城市与活动跨日期移动。
- 新增路线地点后保留手动日期。
- 删除带有关联内容的地点需要确认。
- 夜间交通的次日到达计算。
- 时间重叠、抵达前活动和住宿城市校验。
- 本机序列化、分享精简数据和行程文件导入。
- Markdown 与 HTML 导出包含相同每日内容。

增加静态页面结构测试，确认日历编辑器需要的控件和模块入口存在。最后通过本地静态服务器完成桌面和移动端浏览器验证，检查：

- 三城市路线首次生成。
- 桌面拖拽和移动菜单。
- 城市设置三天停留。
- 添加夜间交通、景点和住宿。
- 冲突提醒、撤销和刷新恢复。
- 地图路线随日历顺序更新。
- 分享链接恢复或长链接文件兜底。
- Markdown 下载、HTML 打开和打印布局。

## 13. 验收标准

- 用户能从三城市地图路线生成可编辑日历，并设置或清空出发日期。
- 用户能让任一城市连续停留 `1-7` 天，其他手动日期不被意外重排。
- 桌面端能拖拽城市和活动，手机端能通过菜单完成同样的跨日移动。
- 用户能填写普通及跨夜交通、添加现有或自定义景点活动、填写住宿。
- 页面能识别时间重叠、抵达前活动、游玩时间不足和住宿城市冲突。
- 新增路线城市只做增量插入；删除带内容的城市前展示确认。
- 刷新页面、旧存档迁移、分享链接恢复和行程文件导入均不会无声丢失内容。
- 地图、行程汇总、Markdown 和 HTML 旅游指南读取同一份日历数据。
- 自动化测试通过，桌面与手机尺寸下无控件遮挡、文本溢出或关键操作缺失。
